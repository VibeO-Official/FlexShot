# ONE BULLET · FlexShot

2D-головоломка с элементами экшена: у игрока **одна пуля**, рикошеты, ограниченное
управление полётом и **бесконечная генерация уровней** с проверкой проходимости.

Проект без внешних библиотек и без сетевых ресурсов: HTML5 + CSS3 + vanilla JS + Canvas.

---

## Быстрый запуск (VS Code + Live Server)

1. Откройте папку проекта в VS Code.
2. Установите расширение **Live Server** (Ritwick Dey).
3. Правый клик по `index.html` → **Open with Live Server**.
   Или запустите локальный сервер вручную:

   ```bash
   npx serve .
   # либо
   python3 -m http.server 8080
   ```

4. Откройте `http://localhost:8080` (или адрес, который выдал Live Server).

> Открывать `index.html` по `file://` не рекомендуется: браузер может блокировать
> localStorage и часть Web Audio API. Используйте локальный сервер.

Первые уровни — обучение: там подсказки объясняют рикошет, управление пулей и энергию.

## Управление

| Действие | Компьютер | Телефон / планшет |
|---|---|---|
| Прицеливание | мышь | палец по арене (перетаскивание) |
| Выстрел | левый клик, `Space`, кнопка **FIRE** | кнопка **FIRE** |
| Подруливание пули | `A` / `D` (или ←/→) | кнопки ◀ ▶ |
| Скорость пули | `W` / `S` (или ↑/↓) | кнопки ▲ ▼ |
| Пауза | `Esc` / `P` | кнопка ❚❚ |
| Перезапуск уровня | `R` | кнопка «Заново» в паузе |
| Звук вкл/выкл | `M` | Настройки |

Управление пулей тратит **энергию**: когда она заканчивается, A/D и W/S перестают работать.
Пока игрок подруливает, время замедляется — это визуальная и игровая помощь, а не читерство:
энергия всё равно расходуется.

## Правила

* Пуля отражается от зеркальных стен и **не застревает** в них (выталкивание + отскок).
* Каждый отскок расходует лимит рикошетов; после лимита выстрел считается неудачным.
* Врагов нужно уничтожить **всех** за один выстрел — пуля пробивает врага насквозь.
* Дверь закрыта, пока не активированы все переключатели её канала.
* Блок-поглотитель убивает пулю, стекло — ломается и пропускает её дальше.
* Телепорт переносит пулю, сохраняя направление.
* Уровень считается пройденным, когда все враги уничтожены.

### Типы поверхностей

| Цвет / вид | Поведение |
|---|---|
| Серые стены | обычное отражение |
| Оранжевые с шевронами | ускоряют пулю при отскоке |
| Фиолетовые пунктирные | гасят скорость |
| Тёмные с красной штриховкой | поглощают пулю (поражение) |
| Голубое стекло | ломается от попадания |
| Голубая дверь | открывается переключателем |
| Голубые ромбы | переключатели |
| Кольца A / B | телепорт |
| Фиолетовые кольца-колодцы | закручивают пулю (с 51-го уровня) |

## Структура проекта

```
index.html          разметка: меню, HUD, экраны, мобильные кнопки
style.css           неоновый адаптивный интерфейс (container queries)
script.js           игровой цикл, ввод, отрисовка, UI, сохранения, испытания
js/engine.js        чистая физика: пуля, отскоки, стены, двери, телепорты, энергия
js/generator.js     процедурная генерация уровней + проверка проходимости
js/yandex.js        безопасная интеграция Yandex Games SDK (необязательна)
tests/              автотесты (Node.js, без браузера)
```

### Почему физика вынесена отдельно

`js/engine.js` не знает про DOM и canvas. Тот же самый код шаг за шагом
симулирует выстрел при генерации уровня. Поэтому проверка «уровень проходим»
использует **ровно ту физику**, которая работает в игре — расхождений нет.

### Как генерируются бесконечные уровни

1. Детерминированный seed: `worldSeed + номер уровня` (mulberry32).
2. Собирается арена из готовых шаблонов (колонны, комнаты, ромб, зигзаг,
   уголки, лестница, кольцо) + движущиеся стены + особые поверхности.
3. Генератор ищет **реальный угол выстрела**, дающий нужное число отскоков.
   С 51-го уровня арену дополняют гравитационные колодцы (они размещаются
   в стороне от решения, но наказывают за неточный прицел).
4. На этой траектории размещаются враги (с фазами движения так, чтобы
   в момент пролёта они были на линии), переключатель с дверью,
   стекло и пара телепортов.
5. Уровень проверяется симуляцией в трёх углах: `aim`, `aim ± допуск`.
   Если хотя бы один не выигрывает — генерируется другой вариант (до 80 попыток).
   В крайнем случае используется простой гарантированный запасной уровень.

Сложность растёт не количеством врагов, а механиками и числом обязательных
отскоков: 0–1 → 2 → 3 → 4 → 5 → до 7 после 100-го уровня. Лимит объектов
ограничен, чтобы не просаживать FPS.

Перезапуск уровня **сохраняет seed** — схема арены та же, можно улучшить результат.
Следующий уровень — новая арена и новый seed.

### Ежедневное испытание

Seed берётся из даты (UTC): `daily-YYYY-MM-DD`, номер арены — из хеша даты.
Все игроки в один день получают одну и ту же арену, без сервера.
Таймер показывает время до следующего испытания (полночь UTC).

## Прогресс, рекорды, достижения

Сохраняется в `localStorage` (`onebullet_save_v1`), а при подключённом SDK —
ещё и в облаке Яндекс Игр:

* текущий и максимальный пройденный уровень;
* победы, попытки, серия побед и лучшая серия;
* лучший счёт по каждому уровню (таблица ограничена 400 записями);
* результаты ежедневных испытаний и серия дней;
* достижения (14 штук) и просмотренные подсказки;
* настройки (звук, громкость, язык RU/EN, меньше эффектов).

Кнопка «Сбросить прогресс» в настройках удаляет сохранение (с подтверждением).

## Подключение Yandex Games SDK

Игра полностью работает без SDK. Для публикационной сборки:

1. Раскомментируйте тег в `<head>` файла `index.html`:

   ```html
   <script src="/sdk.js"></script>
   ```

   При загрузке архива на сервер Яндекса путь должен быть относительным `/sdk.js`.
   На своём домене — `https://sdk.games.s3.yandex.net/sdk.js`.

2. `js/yandex.js` сам выполняет:
   * `YaGames.init()` с обработкой ошибок (игра не ломается без SDK);
   * `features.LoadingAPI.ready()` после инициализации;
   * `features.GameplayAPI.start()/stop()` при входе/выходе из геймплея;
   * сохранение через `player.setData/getData` (при наличии игрока);
   * межстраничную рекламу `adv.showFullscreenAdv()`.

3. Реклама вызывается **только** по кнопке «Следующий уровень», то есть между
   уровнями и после действия игрока. Дополнительно действует локальный
   интервал 90 секунд. Во время полёта пули реклама не показывается.
   При открытии рекламы звук приостанавливается, игра ставится на паузу.
   Если SDK нет — реклама не имитируется и ничего не показывается.

4. Перед публикацией **обязательно** сверьтесь с актуальной документацией
   Яндекс Игр (требования к билду, разметка геймплея, правила рекламы):
   <https://yandex.ru/dev/games/>.

> Важно: проект подготовлен к интеграции, но автор не утверждает, что игра
> автоматически соответствует всем требованиям модерации. Проверка по
> официальной документации и тестирование в Консоли разработчика — на стороне
> публикующего.

### Что не реализовано намеренно

* Нет сервера, регистрации и платных API — базовый геймплей полностью офлайн.
* Нет лидербордов и покупок (для них нужны настройки в Консоли и API платформы).
* Нет «автоматических обновлений контента с сервера»: бесконечные уровни
  генерируются локально, а новые механики появляются только в новых версиях игры.

## Тесты

```bash
npm test                 # все тесты
npm run test:generator   # проходимость уровней 1..300 на разных seed
npm run test:content     # детерминизм seed, ежедневное испытание, рост сложности
npm run test:gameplay    # победа, поражение, рестарт, энергия, запрет второго выстрела
npm run test:save        # сохранение/загрузка/сброс прогресса
npm run test:progression # 12 уровней подряд, NEXT, достижения, рекорды
npm run test:ui          # меню, экраны, HUD, настройки (без браузера)
```

Тесты не требуют браузера: `tests/harness.js` подменяет DOM и Canvas,
использует виртуальные таймеры и `requestAnimationFrame`.

Что проверяет `test-generator`:

* каждый сгенерированный уровень проходим в идеальном угле и с допуском `±aimTolerance`;
* нет врагов в стенах и вне арены;
* у каждой двери есть переключатель и наоборот;
* нет «запасных» уровней (генератор справляется), время генерации в норме.

## Производительность

* Физика — фиксированный шаг 1/120 с, не зависит от FPS.
* Фон арены рисуется один раз в offscreen-canvas.
* Предпросмотр траектории пересчитывается только при изменении прицела.
* Частицы ограничены 420 штуками, «меньше эффектов» уменьшает их число.
* Следующий уровень генерируется в `requestIdleCallback` — без рывков в игре.
* Canvas масштабируется под DPR (не более 2×) и размер окна, включая поворот экрана.
* Пауза при потере фокуса вкладки (`visibilitychange`).

## Как расширять

* **Новый тип стены:** `OB.registerWallType('name', { reflect: true, rest: 0.9 })`
  в `js/engine.js` + ветка отрисовки в `drawWallShape` (`script.js`).
  Физика столкновений уже общая.
* **Новая схема движения врага:** `OB.registerEnemyMove('name', fn)`.
* **Новый шаблон арены:** добавьте функцию в `TEMPLATES` (`js/generator.js`),
  она автоматически попадёт в ротацию.
* **Новая сложность/механика:** правки в `difficulty()` и шагах `buildAttempt()`.

## Известные ограничения

* Звук включается после первого действия пользователя — так требуют браузеры.
* Ежедневное испытание использует UTC: у всех игроков одинаковое, но у игрока
  в другом часовом поясе смена происходит в его локальную полночь UTC.
* Генератор гарантирует проходимость выстрелом без подруливания с допуском
  точности; подруливание может сделать решение проще, но не обязано.
* Сохранения в приватном режиме браузера могут быть недоступны — игра
  продолжит работать, прогресс не сохранится.
